# 直播互动控制器（live-gui）软件介绍

> 版本：1.0.8 ｜ 基于 PyQt5 的某音直播实时互动工具 ｜ 支持 Windows / macOS

**直播互动控制器**是一款本地运行的直播实时数据互动软件。它抓取某音直播间的弹幕、礼物、点赞、进场、关注、粉丝团等实时消息，在桌面上集中展示，并可按类型触发**语音播报**与**58mm 热敏小票打印**，实现丰富的直播互动玩法。

数据仅通过本机进程采集，**不依赖任何远程中转服务器**。使用前请阅读项目根目录的 [免责声明.txt](./免责声明.txt) 与 [LICENSE](./LICENSE)。

## 一、核心功能一览

| 功能模块 | 说明 |
|---|---|
| 实时数据采集 | GUI 进程内由 `WebSocketServerD` 抓取直播间消息，内置的 WebSocket 服务（默认端口 `8765`）实时推送 |
| 消息展示 | 弹幕 / 礼物 / 点赞 / 进场 / 关注 / 粉丝团 / 统计，每类消息可**独立开关** |
| 语音播报 | TTS 文字转语音，按消息类型独立开关，支持"大礼物优先"插播 |
| 小票打印 | 58mm 热敏小票机（ESC/POS）按事件类型独立打印，异步队列不卡界面 |
| 小票模拟 | PC 端模拟小票排版预览，无需真机即可查看打印效果 |
| 3D打印现场 | 照片级实景底图 + 动态打印件，观众消息触发头像圆牌逐层打印 → 机械臂取件投放 → 传送带成品展示，独立动画窗口 |
| 设备激活 | 激活码 + 主板序列号绑定，本地记录激活状态与有效期 |
| 自动更新 | 内置更新器，检测新版本后自动下载、解压、替换主程序 |
| 串口管理 | COM 串口设备的连接与断开管理 |

## 二、数据采集与展示

- 点击「启动服务」后，**在本程序进程内**启动唯一的 `WebSocketServerD` 抓取器；抓到的事件一路给主界面显示/语音/小票打印，一路经 `server/live_server.py` 的事件总线由内置 WebSocket 服务（`8765`）推给外部浏览器与 python 脚本。不再拉起独立子进程。
- 消息类型：**弹幕、礼物、点赞、进场、关注、粉丝团**，主界面按类型滚动展示并统计。
- 每类消息的"显示 / 不显示"在界面上独立勾选，状态保存在 `core/app_state.py`（运行期）。
- 支持某音 / 快手两个平台来源的勾选。

> 使用前需要在界面填入**直播间房间号**和**某音 Cookie**（用于数据抓取鉴权），配置持久化在 `data/app_config.json`。

## 三、语音播报（TTS）

- 按消息类型独立开关：礼物 / 弹幕 / 点赞 / 关注 / 进场，各自决定是否播报。
- 播报采用**单线程队列顺序播放**，避免多语音同时抢喇叭；可一键清空语音队列。
- **大礼物优先**：在"大礼物优先设置"对话框中配置礼物名单，命中时插播优先，不被前面的普通语音堵住。

---

## 四、小票打印（58mm 热敏）

- 目标机型：芯烨（Xprinter）58TS —— 58mm 热敏、ESC/POS 指令、USB 接口。
- 按**事件类型独立渲染**：聊天 / 礼物 / 点赞 / 进场 / 关注 / 粉丝团，每种类型在界面上单独勾选是否打印。
- 打印在**独立守护线程**里顺序消费，主线程只入队，不会卡住界面。
- 三条连接路线（按可靠性排序）：
  1. **自动探测**：在系统打印机列表里按关键字认出 58mm 热敏机，走系统打印队列（推荐，零配置）；
  2. **手填打印机名**：系统里已装官方 USB 驱动时，填系统打印机名即可；
  3. **USB 直连**：填打印机的 VID/PID（16 进制），Windows 需用 Zadig 换成 WinUSB 驱动。
- 跨平台：Windows / macOS 均支持。

## 五、设备激活与自动更新

**激活**
- 软件采集**主板序列号**生成设备标识（`device_id`），首次运行向服务器注册设备；
- 输入激活码激活，**是否过期完全由服务器判定**，本地只保存激活码；
- 启动时会用本地保存的激活码向服务器重新校验：有效则正常使用，已过期则提示“激活已过期”并清除本地激活信息，需重新激活。

**自动更新**
- 启动时检查服务器上的新版本号，与本机版本（`core/app_state.py` 中的 `live_version`）比对；
- 有新版本时由 `updater.exe`（需与 `liveMain.exe` 同目录放置）完成下载、解压、备份与替换。

## 六、界面使用说明

### 1. 激活（首次使用必须）

- 启动软件后，在顶部**设备激活码**输入框输入激活码，点**激活**；
- 未激活时点"启动服务"会提示"请先激活程序"；
- 界面顶部会显示**服务地址**（`ws://IP:端口`）和**设备码**（绑定主板序列号）。

### 2. 抓取直播间数据

1. 填写**某音房间号**（必填）；
2. 粘贴**某音 Cookie**（可选：从某音网页版复制，可提升礼物数据获取成功率）；
3. 点**启动服务**开始抓取，**停止服务**结束；
4. 关闭窗口时会自动停止服务与抓取线程。

### 3. 消息显示 / 语音播报 / 打印（各自独立勾选）

| 区域 | 开关项 | 附加按钮 |
|---|---|---|
| 消息记录 | 礼物 / 聊天 / 点赞 / 关注 / 进场 / 统计 / 粉丝团 | — |
| 语音播报 | 礼物 / 聊天 / 点赞 / 关注 / 进场 | 清空队列、大礼物优先"设置" |
| 打印 | 聊天 / 礼物 / 点赞 / 进场 / 关注 / 粉丝团 | 小票模拟、手机预览、3D打印 |

**3D打印**：点击后弹出独立的打印现场窗口（照片级实景底图 + Qt 动态叠加，不依赖浏览器/WebEngine，不新增任何端口）：
静态场景来自 `assets/images/printer3d_bg.jpg`，按真实直播间构图生成——暖光房间、木地板与木柜、金属龙门架打印机、四色线材、玻璃热床、橡胶传送带；
Qt 只叠加会动的部分：逐层挤出的观众头像圆牌、当前层熔丝高光、机械臂取件、落带后随传送带向右运走的成品。
**机械臂取件**：打印完成的瞬间，左侧机械臂按二连杆逆运动学动作——伸向热床 → 夹爪闭合 → 抬起 → 转向履带 → 松爪放件 → 回待机位（约 2.9 秒一轮），成品在松爪那一刻才交给传送带；动作期间不启动下一张打印。
机械臂不是画出来的插画：下臂、上臂、关节、底座、夹爪是从实景底图抠出的照片素材（带 alpha），运行时按关节角度旋转贴图；待机时直接使用底图里的静态实拍臂，动作时先贴补丁擦除静态臂再重绘，无重影。素材缺失会自动退回「打印完直接落带」，窗口不报错。
运行模式参照真实直播间录屏：成品在热床右侧短距离落带，随传送带**从左向右**匀速运走，多张牌按出片间隔自然排队、右端出画；不做抛物线飞送，也不推挤旧牌。
底图与 6 张机械臂素材均已加入 `liveMain.spec` 的 `datas`，打包后按 `sys._MEIPASS` 查找；缺图时自动退回内置的程序化场景（含完整动态机架），窗口仍可用。
礼物事件插队但不打断当前打印；状态做成**固定在左立柱前方的黑色实物电子屏**（金属外壳 + LCD + 支架），独立显示「打印状态 / 剩余打印 / 今日完成 / 进度」，不是悬浮 HUD，也不叠加任何角标。
数据与「小票模拟 / 手机预览」同源，由 `ReceiptSimulator.add_event()` 转发真实抓到的事件；空闲补偿的演示事件**不会**进入该画面。
窗口底部提供「模拟一条 / 暂停 / 清空」，1280×720 纯画面可直接用 OBS 窗口采集。

### 4. 串口设备

下拉选择 COM 口 → **刷新**重新枚举 → **连接** / **断开**。

## 七、对外接口

数据服务启动后，**对外只暴露一个 WebSocket 端口 `8765`**（全项目唯一，以界面顶部显示的地址为准），外部页面/程序连它即可消费实时互动数据；`8766` 是本机 HTTP 配置接口，不是 WS 服务。**推送的是抓取器拿到的原始事件**：不加工、不过滤、不补发，由消费端自行解析。

### 1. WebSocket 实时推送

- 连接地址：`ws://127.0.0.1:8765`
- 连接建立后立即收到一条上线通知：

```json
{"source": "系统", "message": "connected", "timestamp": "2026-10-29T13:00:00"}
```

- 之后每条直播间互动实时推送一条 JSON，即 `WebSocketServerD` 输出的原始 dict（不再额外附加 `timestamp` / `raw`），常见字段如下：

| 字段 | 说明 |
|---|---|
| `source` | 事件类型：`聊天` / `礼物` / `点赞` / `进场` / `关注` / `粉丝团` / `系统` |
| `nickName` | 用户昵称 |
| `msg` | 聊天内容（仅 `聊天` 事件） |
| `giftName` / `giftCount` | 礼物名称与数量（仅 `礼物` 事件） |

示例：

```json
{"source": "礼物", "nickName": "小明", "giftName": "小心心", "giftCount": "1"}
```

### 2. 仅 WebSocket，无 HTTP 查询接口

当前只提供上面的 WS 实时推送；原先的 `/health`、`/events`、`/gift/latest`、`/stream` 等
HTTP 查询接口与网页玩法页面已移除。外部脚本直接连 `ws://127.0.0.1:8765` 消费即可。

### 3. 内部同步接口（GUI 进程，端口 8766）

- `GET /live-config`：返回 GUI 勾选状态快照，供本机外部程序读取；不是 WS 服务，也不参与数据推送。

## 八、常见问题

| 现象 | 处理 |
|---|---|
| 打包时 `PermissionError: [Errno 13]` 指向 dll | 360 等安全软件实时防护拦截所致：把项目目录加入信任区，或打包时退出安全软件（脚本已内置自动重试） |
| 激活报 `127.0.0.1:7897` 超时 | 7897 是本机代理端口，不是目标地址；检查系统代理或直连后再试 |
| 语音不播报 | 检查对应消息类型的语音开关是否勾选 |
| 小票打印没反应 | 优先用"自动探测"；确认打印机已装官方驱动并出现在系统打印机列表 |
